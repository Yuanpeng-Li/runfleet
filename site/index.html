RunFleet
Install Guide GitHub

All your Slurm jobs and GPU machines in one terminal.

Queues, GPU use, logs and the reasons jobs failed, from every cluster and workstation you can ssh into. Nothing gets installed on the remote side.

Below is RunFleet itself on a simulated fleet of three Slurm clusters and two GPU workstations: screens recorded from the real app, replayed in your browser.

Install

One line on Linux, macOS or WSL. It needs only your system ssh client. The script installs uv if you do not have it (uv brings Python 3.11 when the system has none), then RunFleet. Run the same line again to update.

There is no PyPI release yet, so installs come straight from GitHub.

$ curl -LsSf https://raw.githubusercontent.com/Yuanpeng-Li/runfleet/main/install.sh | sh

Try it in your terminal first

The same simulated fleet; no account or cluster needed.

$ uvx --from git+https://github.com/Yuanpeng-Li/runfleet runfleet --demo

Windows 10 or 11, in PowerShell preview

> powershell -ExecutionPolicy ByPass -c "irm https://raw.githubusercontent.com/Yuanpeng-Li/runfleet/main/install.ps1 | iex"

Needs Git for Windows and the built-in OpenSSH client, 8.1 or newer. See the Windows notes.

By hand, with uv

$ uv tool install git+https://github.com/Yuanpeng-Li/runfleet

The rounds it does for you

One SSH round trip per host per refresh, about the load of watch -n 15 squeue --me. Everything ends up in one view you drive from the keyboard.

Commands RunFleet runs for you, where you would run them, and what it shows
Instead ofOnYou see
squeue --me each cluster's login node Your running (R), pending (PD) and failed (F) jobs on every host, the GPUs you hold, and the next job in line with its estimated start.
sinfo each cluster Free GPUs per partition, with your usual GPU types listed first.
nvidia-smi the compute node your job landed on Utilisation and memory for each GPU inside a running job, and which process sits on which GPU. A GPU idling inside a busy job shows; Slurm accounting only knows the job's average.
sacct and the end of the log each cluster, after the job ends A cause such as OOM-GPU, NCCL or TIMEOUT linked to the log line behind it, plus a hint for the --time or --mem to ask for next time.
sprio and sshare each cluster, while a job waits The priority factors holding it back and your fair share. Evidence, not a promised start time.
tail -f another terminal The job's output, following live. Ctrl+F searches the logs of your recent jobs.
Logging back in to check at 2 a.m. A notification when a job fails, is requeued or nears its time limit, and a note on what changed while you were away.

What it asks of the cluster

Nothing installed. It uses your OpenSSH client and ~/.ssh/config as they are (ProxyJump, ControlMaster, keys, Duo) and runs only commands already on the host.

Little load on the login node. One round trip per host per refresh. Hosts that are off screen are polled less often, and polling pauses when you walk away.

No drama when a host goes away. An unreachable host, an expired login or a hung nvidia-smi becomes a badge and a retry. The last known data stays on screen.

Nothing happens without a yes. Cancel, hold, requeue and terminate are confirmed and show the exact remote command. --readonly turns them all off, and partitions or QOS you mark as protected are never touched.

First run

Host names are your own ~/.ssh/config aliases. RunFleet works out whether each one is a Slurm cluster or a plain GPU machine.

More in the user guide and the configuration reference.

# first run: pick hosts from your ~/.ssh/config
runfleet
# only these ssh aliases this time
runfleet gpu-a mylab
# why does a host not work?
runfleet doctor gpu-a
# block until a job ends
runfleet wait gpu-a:123456 && ./eval.sh
# for your prompt or tmux, no ssh
runfleet status --short
