What it does for you

It does the rounds of squeue, sacct, nvidia-smi and tail -f for you: one SSH round trip per host per refresh, everything in one keyboard-driven view.

Every host at a glance

One card per host: your running, pending and failed jobs, the GPUs you hold, free GPUs per partition, the next job in line and login-node load. Workstations get per-GPU bars.

Live GPU readings inside a job

Slurm accounting only knows a job's average. Open a running job and RunFleet reads its own node: per-GPU utilisation and memory, and which process sits on which GPU, so a GPU idling inside a busy job shows.

Why jobs end and wait

Ended jobs get a cause (OOM-GPU, NCCL, TIMEOUT, …) linked to the log line behind it. Pending jobs show the priority factors that hold them back.

Nothing to install remotely

It uses your OpenSSH client and ~/.ssh/config as they are (ProxyJump, ControlMaster, keys, Duo) and only runs commands already there.

Calm when hosts are not

An unreachable host, an expired login or a hung nvidia-smi becomes a badge and a retry; the last known data stays on screen. Failures and jobs near their time limit raise a notification.

Safe by default

Every action (cancel, hold, requeue, terminate, …) is confirmed and shows the exact remote command. --readonly turns them all off, and partitions or QOS you mark as protected are never touched.

Install

The script installs uv if you do not have it, then RunFleet; run it again to update. Python 3.11 or newer, which uv brings along when the system has none.

Linux, macOS, WSL

$ curl -LsSf https://raw.githubusercontent.com/Yuanpeng-Li/runfleet/main/install.sh | sh

Windows preview

> powershell -ExecutionPolicy ByPass -c "irm https://raw.githubusercontent.com/Yuanpeng-Li/runfleet/main/install.ps1 | iex"

Windows 10 or 11, in PowerShell. Needs Git for Windows and the built-in OpenSSH client (8.1 or newer); see the Windows notes.

By hand

$ uv tool install git+https://github.com/Yuanpeng-Li/runfleet

Get started

runfleet                    # first run: pick hosts from your ~/.ssh/config
runfleet gpu-a mylab        # only these ssh aliases this time
runfleet doctor gpu-a       # why does a host not work?
runfleet wait gpu-a:123456 && ./eval.sh   # block until a job ends

Host names are your own ~/.ssh/config aliases; RunFleet works out whether each is a Slurm cluster or a plain GPU machine. More in the user guide and the configuration reference.
